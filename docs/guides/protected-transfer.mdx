---
title: Protected transfer
description: "Escrowed, code-claimed USDC transfers that make a wrong send recoverable."
---

A protected transfer locks USDC in a contract instead of sending it straight to an
address. The recipient claims it with a secret; if the address was wrong or
poisoned, the wrong party cannot claim and you reclaim. It replaces the "send $1
first and wait" ritual.

![The send form](/screens/02-send-form.png)

## Send

```ts
import { approveUsdc, sendProtected, generateClaimCode } from '@ctrl-arcz/sdk';
import { parseUnits } from 'viem';

const amount = parseUnits('5', 6);
const secret = generateClaimCode(); // { secret, code, salt, claimHash }

await approveUsdc(clients, amount);
const { transferId, txHash, deadline } = await sendProtected(clients, {
  configId, to: recipient, amount, claimHash: secret.claimHash,
});
```

Give the recipient `secret.secret`, the grouped 16-character string. It carries all
80 bits and the salt is derived from it, so that one string is the whole
credential. Anyone can submit the claim, but the funds always go to the recorded
recipient, so a claim is front-run-safe.

![The money locked, waiting for the secret](/screens/06-send-locked.png)

Every open transfer stays visible and cancellable while it waits.

![Active transfers](/screens/07-active-transfers.png)

## Claim

The recipient types the string; `fromSecret` turns it back into the pair the
contract wants.

![Entering the secret](/screens/08-claim.png)

```ts
import { claim, fromSecret } from '@ctrl-arcz/sdk';

const { code, salt } = fromSecret(whatTheUserTyped); // null-safe via normaliseSecret
const txHash = await claim(clients, transferId, code, salt);
```

![Claimed](/screens/09-claim-received.png)

<Warning>
A wrong code does **not** revert on chain; the contract returns `false` and counts
an attempt, because the attempt counter has to survive for the five-guess lockout
to bind. So a mined transaction is not proof of success. The SDK's `claim` reads
the receipt and **throws** `WrongClaimCodeError` (carrying `attemptsRemaining`) or
`TransferLockedError`; on success it returns the transaction hash. Never treat a
mined tx as a claim.
</Warning>

## Cancel and refund

Unclaimed money belongs to the sender. There is no deadline on getting it back.

<CardGroup cols={2}>
  <Card title="cancel(transferId)" icon="rotate-left">
    Sender only, allowed any time before a claim lands, and on a locked transfer.
  </Card>
  <Card title="reclaimExpired(transferId)" icon="clock-rotate-left">
    Callable by anyone once the recall window lapses; funds only ever go back to
    the sender. No keeper required.
  </Card>
</CardGroup>

```ts
import { cancel, reclaimExpired, getTransfer } from '@ctrl-arcz/sdk';

await cancel(clients, transferId);
await reclaimExpired(clients, transferId);
const t = await getTransfer(clients, transferId); // status, deadline, attempts, ...
```

## Approve-less sends

To skip a per-send `approve`, use Permit2: one-time `approvePermit2(clients)`, then
`sendProtectedWithPermit` signs an off-chain permit per send.

```ts
import { approvePermit2, sendProtectedWithPermit } from '@ctrl-arcz/sdk';

await approvePermit2(clients); // once
await sendProtectedWithPermit(clients, { configId, to, amount, claimHash });
```
